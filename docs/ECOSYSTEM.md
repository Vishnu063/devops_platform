# Optional ecosystem sources and monitoring

This continuation builds on the existing LiveFlow branch and keeps its standalone Docker/Kubernetes/Jenkins topology and toolkit. No existing PR is merged. Run `python liveflow/server.py --port 8769` to open a loopback read-only viewer; absent Docker or Kubernetes yields a disconnected source, not a failed application startup. `--context OWNED_CONTEXT --namespace OWNED_NAMESPACE --cluster-events` opts into namespaced event reads. `--helm` adds fixed Helm list reads; `--argocd-namespace argocd` reads Application CRs using the selected context, never Argo sync. Confirm read-only RBAC from existing examples. Collectors cannot create, patch, delete or approve changes.

Install `requirements-ecosystem.txt` only for the optional Ops Pilot view. `--ops-pilot-url http://127.0.0.1:8767` reads `/integration/state` using OPS_PILOT_READ_TOKEN from private environment configuration. The matching receiver key is read-only and cannot enter the owner approval API. Missing package, token, network, CLI or CRD is a labelled disconnected source; it does not mean the resources were deleted. Security scanner findings and an external log backend are explicitly unconfigured rather than reported clean.

`monitoring/ecosystem/compose.yml` defines optional `monitoring` and `ui` profiles. Nothing in it runs without a profile. Reuse existing monitoring first; these are alternative isolated ports 19090/19093/19115/13000, not replacements for an existing installation. This profile is Linux-only and binds host HTTP listeners to loopback. Set private OPS_PILOT_READ_TOKEN_FILE and OPS_PILOT_ALERT_TOKEN_FILE mounts to match receiver credentials, and GRAFANA_ADMIN_PASSWORD through your protected environment. Use Ops Pilot's `scripts/setup-ecosystem.py` to create a new private configuration and owner-writable monitoring data directories. Load its integration.env into the receiver and Compose environment. Prometheus and Alertmanager run as that configured owner UID/GID, so their 0600 credential mounts remain private; never make keys world-readable to fix permissions.

`docker compose -f monitoring/ecosystem/compose.yml --profile monitoring up -d` starts only opted-in Prometheus/Alertmanager/Blackbox. Review the YAML first: customize the sample service ID and endpoint in prometheus.yml/alerts.yml, and the receiver loopback URL in alertmanager.yml. `--profile ui` additionally starts Grafana with a protected login; its provisioned dashboard shows application health, deployment status, active incidents, resources, firing alerts and recovery. Alert history comes from Ops Pilot's private durable event/audit ledger. Prometheus stores metrics; no log store is installed. Existing Triage collectors retain selected log-signature counts, not raw log archives. Connect an existing appropriate log backend separately if required.

Application-failure routing is exercised by the disposable cross-repository acceptance driver. Restart/resource/rollout expressions are prepared configurations and require actual cAdvisor/node-exporter/kube-state-metrics series and separate controlled triggering; missing series are not verified alerts. This profile reads existing host exporters and does not mount the host root or Docker socket. CloudLaunch textfile metrics need an explicitly configured collector mount. Avoid high-cardinality release IDs as Prometheus labels; immutable identifiers stay in deployment events.

Prometheus limit 192 MiB/0.5 CPU, Alertmanager 64 MiB/0.25 CPU, Blackbox 48 MiB/0.25 CPU, optional Grafana 384 MiB/0.5 CPU are configured ceilings, not measured capacity guarantees. No claim is made that the full Kubernetes/Jenkins/model stack fits in 8 GB. Keep large models disabled and concurrency one. No log, cluster, Argo, Helm, K8sGPT or customer runtime is silently installed or configured.

`python -m unittest discover -s tests -p test_ecosystem_sources.py -v` checks disconnected operation and fixed read-only Argo collection. Actual Docker/Prometheus/Alertmanager/event/approval/recovery results are recorded in Ops Pilot's integration CI/runbook; collector fixtures do not establish live cluster acceptance. Prometheus/K8sGPT use Apache-2.0 and Grafana AGPL-3.0; upstream source is not copied. Model/provider rights remain separate.

Collection concurrency is bounded to one pass. If an optional source is slow, overlapping browser polls receive an explicitly busy cached snapshot rather than starting more collectors or queueing unbounded work. Cached timestamps remain unchanged; cached data is not fresh evidence. The concurrency regression test blocks a source and confirms a second request does not invoke it.
