# Optional ecosystem monitoring

This directory extends the existing Platform monitoring stack; it does not start anything on import or require Kubernetes for the application/dashboard to open. The app's `/ecosystem` view and `/api/integrations` report explicit disconnected states; use the existing toolkit and explicit Kubernetes contexts for real cluster, pod, event, Helm and GitOps reports. Connection configuration is not evidence of connectivity.

Render placeholders in `prometheus.yml` and `alertmanager.yml` into a private directory: `APP_PORT`, `PILOT_PORT`, `ALERTMANAGER_PORT`, `SERVICE_NAME`, `RULES_FILE`, `TOKEN_FILE`. The token file holds a secure `OPS_PILOT_INGEST_TOKEN` shared with Pilot and must be mode 600, outside Git. Run `promtool check config` and `amtool check-config` before starting their respective services. Monitoring/Pilot in this minimal lab are host processes bound to loopback. No Docker host networking or public webhook is required.

`SERVICE_NAME` must exactly match Pilot's configured container. Alertmanager sends v4 firing/resolved webhooks with bearer authentication. Prometheus scrapes Pilot using its bearer file. Existing node-exporter/cAdvisor monitoring remains the source for CPU, memory and restart metrics; kube-state-metrics requires a separately configured Kubernetes scrape job. The sample restart/pressure rules do not produce data when those optional exporters are absent. For an actual alert route, attach the exact configured `service` label; do not route unrelated Kubernetes/host alerts to a single Docker app as if it owned them.

`dashboard.json` contains application health, deployment-event counts, active monitoring alerts, memory utilization, endpoint recovery and alert history over the selected range. Import it into existing Grafana and map the Prometheus datasource UID to `prometheus`, as in existing provisioning. Grafana 12.2.0 provisioned all six panels and authenticated datasource queries confirmed the live CloudLaunch target healthy before failure and after recovery. Browser visual acceptance is unrun because Chromium download was blocked. Historical `ALERTS` reflects Prometheus retention, not an immutable incident audit database. Reports/audit are owned by Pilot. Logs are collected as bounded Triage signatures or an existing configured log backend; Grafana itself is not log storage.
